# Podtrim（旧 himadan-edit）— ひま談 編集自動化パイプライン

「ひまじんプログラマーの週末エンジニアリングレッスン」の編集を自動化する。
3人がそれぞれ別録音した音源を、**3本のまま**（1本にミックスせずに）同期・カットする。

アプリの名前は **Podtrim**（ポッドキャスト＋刈り込む。2026-10-18 に倉田さんが5案から決めた）。リポジトリのフォルダ名・
回のデータの置き場所（`~/Library/Application Support/himadan-edit/`）・環境変数（`HIMADAN_*`）は前の名前のまま。
GitHub には、名前・フォルダの場所・本物の回の記録を消して、履歴の無い新しいリポジトリとして「こういうツールを作りました」の形で公開する
予定（倉田さん OK・最後にまとめて。かいちさん・のりさんにも渡せる）。

**公開と、かいちさん・のりさんとの共有**（2026-10-19・倉田さん「カイジさんとノリさんに共有できるように、ヒマプロの GitHub の方に…新しくリポジトリ作ってプッシュして…プルできるように」→ 同じ日に「一応俺のさ、GitHub にもピン止めしたい…就活のためとかにもね」「組織に非公開でする意味ある？個人で公開してるなら」）:
GitHub の倉田さんの公開リポジトリ `jumpei-kurata/podtrim`（ライセンス MIT）1つにした。かいちさん・のりさんもここから clone し、倉田さんの
プロフィールにピン止めする（初めの案の組織 `himapro-community` の非公開は作らない＝同じ中身が公開なら隠す物が無く、2か所だと更新が二度手間。
組織で公開してピン止めすると、プロフィールに組織の名前で出て、倉田さんが作った物と分かりにくい）。中身はこのリポジトリの写しで、
履歴は持っていかない（公開用の履歴だけ。作者は GitHub の noreply のメール）。README.md は英語（`docs/share-README.en.md`・GarageBand を

## 設計の中核

> **解析するときは混ぜる。成果物は混ぜない。**

```
3本の元ファイル（読むだけ・絶対に壊さない）
   ↓
[解析] 各トラックの無音区間 → 積集合 = 全員が無音の区間 → カットリスト(JSON)
   ↓
[適用] 同じカットリストを3本それぞれに別々に適用
   ↓
3本の別ファイル（頭出し済み・同期維持・カット済み）
```

同じサンプル番号で切るので、**同期は構造的に保証される**。

## なぜ3本のまま維持するのか

1. 自動編集が正しいとは限らないので、後から自分で直せる状態を保つため
2. 喋りが被った時に「誰の声を残すか」を人間が判断するため（BGM・末尾広告も同様）

このツールは**被り区間を検出して候補を出すだけ**で、誰を消すかは決めない。

## 前提

- macOS / ffmpeg / Node.js。説明文の文字起こし（mlx_whisper）だけは Python 製で、`uv tool install mlx-whisper` で入れる（使わないなら不要）
- 実装は ffmpeg + Node.js のみ。外部ライブラリなし（`npm install` 不要）。Mac のアプリの土台（Electron）は `app/build.js` が用意する

## 録音形態で同期の原理が変わる（重要）

ひま談は**3人が別々の場所で録音（リモート）**。両方に対応しているが、効く手がかりが違う。

| | 同室録音 | リモート録音（ひま談はこちら） |
|---|---|---|
| 拍手 | 「1回の同じ音」が3本に入る → **波形照合できる** | 各自が自分の手を叩く → **波形は別物。照合できない** |
| 他人の声 | 自分のマイクにも入る → 相関が効く | 入らない → **相関は効かない** |
| 使える手がかり | 拍手の波形 / 部屋の音の相関 | **拍手の鳴った時刻** ＋ **会話の譲り合い** |
| 精度の限界 | サンプル単位まで詰められる | **拍手のタイミング誤差（人間＋回線）が残る**。数十ms程度 |

リモートで使う「会話の譲り合い」とは、3人は基本1人ずつ喋るので、正しく揃った位置では
A が喋る間 B は黙る＝包絡が逆相関になる、という性質。ズレていればランダムに重なって相関は0付近。
ただしこの谷は1〜2秒と幅広く単独では位置を決められないので、**秒単位で離れた偽の候補を落とす用途**に使い、
最終的な位置は拍手の時刻で決める。`sync.js` はどちらの形態かを自動判定して `recordingType` に出す。

**最優先は「はっきりした手拍子」**（2026-10-17・3人の実音源で分かった）。基準と相手の両方で、
音合わせの拍手が1つだけはっきり立っていれば、その時刻の差でズレを決める。人が GarageBand で手拍子の
波形を見て揃えるのと同じやり方で、ピープルウェアー回では倉田さんの手編集の揃え方と1ミリ秒以内で一致した。

- 拍手は大きさだけでなく**形**で見分ける: 直前が静か（「よーおっ」の「っ」で一瞬黙る）・余韻が短い。
  机やマイクに触れた音は余韻が長く、話の途中の笑いや物音は直前が静かでない。実音源8本（3回分）で、
  この2つを満たしたのは音合わせの拍手だけだった
- 小さな物音（キーボード等）を拾わないよう、拍手はその録音の冒頭で一番大きい音の半分以上を求める。ただし、ほかの拍手らしい音の
  5倍以上で、冒頭の普段の音（5ms ごとの高い音の山の上位 1%）の 2倍以上あれば、4分の1 まで認める（2026-10-23・個人開発回の3本目:
  拍手が、拍手でない大きな音の 0.40倍しかなく決まらなかった。`src/clap.js`）。過去の録音 144本で、これで判定が変わるのはこの1本だけ
  （音合わせの拍手は普段の音の 2.23倍以上。拍手を切った後の録音の、話の間のクリック音は 0.95倍で拾わない）
- 会話の譲り合いは**3人だと打ち消される**（3人目が喋る間は残り2人がそろって黙る＝正の相関になる）。
  手拍子がはっきりしない3人の回は自動では決まらない。その時は「頭揃え待ち」の回として読み込み、画面の「頭を揃える」窓で
  手拍子を選んで揃える（下の「編集画面」の「頭を揃える」）

## 使い方

```bash
# 1. 頭出しオフセットを算出（手拍子と相互相関の両方から候補を集めて採点）
node src/sync.js 元音源/A.wav 元音源/B.wav 元音源/C.wav > work/sync.json

# 2. 頭出しを揃える（根拠が弱ければここで停止して候補を提示する）
node src/align.js work/sync.json work/aligned

# 3. 全員が無音の区間を検出（ファイルは変更しない）
node src/analyze.js work/aligned/*.wav > work/cuts.json

# 4. 3本それぞれに同一カットを適用
node src/apply.js work/cuts.json work/final

# 5. 同期が保たれているか検証（壊れていれば終了コード1）
node src/verify-sync.js work/cuts.json work/final

# 6. 発話の被り区間を検出（消さない。候補を出すだけ）
LABELS_OUT=work/overlap-labels.txt node src/overlap.js work/aligned/*.wav

# 7. 検品用の出力（継ぎ目ラベル + 捨てた音声＝全トラックを重ねたもの）
node src/report.js work/cuts.json work/review
```

`report.js` は長いフィルタをファイルで ffmpeg に渡す。ffmpeg 9 で前の指定（`-filter_complex_script`）が無くなり、検品用の出力だけ止まっていたので、
ffmpeg 7 からの `-/filter_complex <ファイル>` に替えた（2026-10-22。6 以前の ffmpeg では前の指定でやり直す）

## 編集画面（GarageBand 風・作成中）

GarageBand に移さず、この画面だけで編集を終わらせるためのもの（意図: `docs/intent/2026-10-17-standalone-editor-app.md`）。
1回分を仕上げる手順（録音 → 新しい回 → 確認 → 書き出し → 説明文 → ART19。かいちさん・のりさんにも渡せる形）は [`docs/guide.md`](guide.md)。

```bash
# 新しい回は、ふつうは画面に3人の録音を落として作る（下の「ファイルを落とす」）。中では ui/import.js が次の4つを続けて走らせる:
#   src/sync.js → src/align.js → src/analyze.js → ui/prep.js
# 手で作る時: 自動編集の結果（3. の cuts.json）から「回」を作る。--sync で生の録音と頭揃えのずれも記録する（書き出しで頭揃えをやり直すため）
node ui/prep.js work/cuts.json mamori-2026-10-17 守りのトークン抑え --sync work/sync.json --bgm <BGM> --cm <CM>

# 前からある回に「話し声の大きさ」と「全員が黙っている所」を測って足す（prep.js で作った回は済んでいる・編集の状態は消えない）
node ui/analyze-project.js mamori-2026-10-17

# 画面を開く（この Mac の中だけで動く）→ http://localhost:8899
node ui/serve.js 8899

# 書き出し（ふつうは画面右上の「書き出す」から。保存してある編集の状態どおりに書き出す）
node ui/export.js mamori-2026-10-17 --format wav   # mp3 も可
```

- 回のデータ（再生用の音声・波形・編集の状態 `state.json`）は **`~/Library/Application Support/himadan-edit/projects/<回のID>/`**（`ui/data-dir.js`・環境変数 `HIMADAN_DATA` で変えられる）。リポジトリの中に置くと、作業用の分岐を片付けた時に編集の状態ごと消える
- **回を消す＝「整理する…」**（2026-10-19 追加・倉田さん「このポッドトリムで作ってるこのファイルたち…どこで消せるの？なんか一生溜まっちゃうじゃん」→ 初めは1回ずつ消す「この回を消す…」にしたが「一個ずつしか消せないんでしょ？複数で一気にバーッと消せたりもできないしさ」→「Bでお願い、作って→整理する、とかだけでもいいかもしれないけどね」で今の形）: 1回で約260MB（9割が再生用の声 `voices.wav`。元の録音〈1回 約1.75GB〉の7分の1ほど）。上の帯の回の名前を押した一番下の「整理する…」で、全部の回を1行ずつ（名前・作った日時・最後に触った日・書き出し済みか・大きさ）並べた窓が出る。消したい回に印を付けて「◯回をゴミ箱に入れる」で、まとめて Mac のゴミ箱に入れる（回を開かなくてよい）。消えるのは回のフォルダだけ（元の録音と書き出したファイルは消えない）。選んだ回の大きさ（ゴミ箱を空にすると空く分）と全部の大きさも出る。ゴミ箱へは macOS 15 からある `/usr/bin/trash` で入れる（入れた物は Finder の「戻す」で元の所に戻る＝試しのフォルダで、入れる→戻すまで確かめた。この命令が無い Mac〈macOS 14 まで〉は Finder に頼む＝未確認）。書き出し・説明文づくり・回づくりの最中の回は印を付けられない（「書き出しの最中なので消せません」）。開いている回を消した時は、いちばん最近触った回を開き、ゴミ箱でのフォルダの名前を知らせる。開いている回が残る時は、窓の中で知らせて一覧を作り直す。サーバーは `GET /api/projects?detail=1`（大きさ・書き出し済みか・動いている仕事）と、回ごとの `POST /api/projects/<id>/trash`（`ui/serve.js` の `moveToTrash`）。試す時は環境変数 `HIMADAN_TRASH` のフォルダへ移す（Mac のゴミ箱を使わない）
- 同じ名前の回が並んだ時は、回の名前の一覧に作った日を添える（「守りのトークン抑え（10/17）」。同じ日なら時刻まで・2026-10-19）
- 同じ回を作り直すと、前の編集の状態は `state.json.old` に退避する（カットや人数が変わると合わないため）。画面も、別の回の状態は使わない
- サーバーは 127.0.0.1 で待ち受け、Host も確かめる（公開前の録音を外に出さない）。壊れた形のアドレスでも止まらない。書き換える依頼（保存・書き出し・取り込み）は、画面が付ける `x-himadan` の印が無いと断る（よそのページから送らせない）

- 声は「人数分のチャンネルを持つ1つのファイル」を1本で再生し、画面側で人ごとに分ける。何人いてもずれない
- 操作は GarageBand に合わせた（倉田さんの要望・2026-10-17）: Space 再生／停止・⌘T 再生位置で分割・クリックで塊を選ぶ（⇧で足す）・⌫ 消す（隙間は残る）。GarageBand に無い ⇧⌫「消して詰める」（選んでいなければ、3人とも消えている所を詰める）を足した。**選んでいる時は、選んだ時間を全員分消して詰める**（1人だけ選んでいても。「3人分選択」を先に押さなくてよい・2026-10-19・倉田さん「そもそも消して詰めるっていう時って3つとも選択した時じゃないと反応しないし」。離れた所を選んでいた時は、選んだ所ごとに全員分にする）
- **選んでいる時のキー**（2026-10-19・倉田さん「3人分選択して詰めるとか、なんかあそこら辺ショートカットコマンドあったらめっちゃ便利かも」）: E＝選んだ時間を全員分選択（バーの「3人分選択」と同じ・Everyone）・I＝フェードイン（In）・O＝フェードアウト（Out）。「3人分選択して詰める」は ⌘⌫（⇧⌫ でも）だけでできる（上のとおり、選んだ時間を全員分消して詰める）ので、別のキーは作らなかった。何も選んでいない時に押すと、先に選ぶよう知らせる
- **選んでいない時の ⌘⌫＝再生位置のすぐ左の塊を、全員分消して詰める**（2026-10-19・倉田さん「コマンド T でカットして、そのままコマンドを動かさず、コマンド何かで左の3つの録音のパートを消して詰める…いちいちさ、どれを削除するのかって選択しなきゃいけないのがさ、めんどくさいのよ」「コマンド T をして2、3秒放置して、もう一回コマンド T をして、もう一回コマンドプラスなんとかのコマンドを押せば、その削除の部分をバッと消して左に詰める」）: 選ばなくてよい。塊の区切りは画面と同じ（⌘T の印・自動で削った継ぎ目・消した所の端。誰の物でも）。押すたびに左へ1つずつ消す（再生位置が詰めた所の終わりにある時は、その頭から左を見る）。⌘T を2回押して挟んだ間に継ぎ目（目盛りの赤・灰色の ▲）があると、1回目は継ぎ目までなので、もう一度押す。「1つ前の ⌘T の印まで消す」にしなかったのは、倉田さんの画面の左の塊が継ぎ目（確認済みの灰色の ▲）から始まっていて、⌘T を1回だけ押した時にずっと前まで消えてしまうため。消した範囲と秒数を知らせ、⌘Z で戻せる。ボタンは作らない（選ばずに使う物なので、選んだ時のバーに置けない。下のキーの1行と「?」の窓に出す）。前は ⌘⌫ も ⌫ と同じだった。「元の音」の並びで、再生位置が切る所（暗い所）の中にある時は使えない（左に見えているのが切る所なので、手前の塊を消してしまう。「ここは切る所の中です」と知らせる・2026-10-19 の監査）
- **消す操作の整理**（2026-10-19・倉田さん「コマンドが分かんなくなってきちゃった。なんかそこら辺の削除の挙動がちょっと分かりやすく整理して」）: 覚えるのは2つ。**⌫＝選んだ人の声だけ消す**（時間は詰めない＝隙間が残る。1人の咳や物音など）。**⌘⌫＝3人分消して詰める**（時間ごと消える）＝選んでいれば選んだ時間、選んでいなければ再生位置のすぐ左の塊（文字の ⌫ と同じ考え方＝選んでいればそこ、なければ左）。⇧⌫ は前からのキーで、選んでいる時は ⌘⌫ と同じ（選んでいない時は、3人とも消えた所だけを詰める）。画面の表示（下のキーの1行・「?」の窓・ボタンの説明・消した時の知らせ）は ⌘⌫ にそろえた（倉田さん「⇧⌫これってオプションってこと？なんか押しづらいよね」）。同じ日の少し前の作り（ab233d2）では、選んでいる時に ⌘⌫ を押すと、選んだ所を無視して再生位置の左を消していた（思っていない所が消える）ので、選んでいれば選んだ所にした。⌫ で消した時の知らせは「消しました（選んだ人の声だけ・隙間は残ります。時間ごと3人分消す時は ⌘⌫）」、⌘⌫ で選んだ所を消した時は「選んだ所を3人分消して詰めました」
- 被り（2人以上が同時に話している所）は黄色の印と「被り ▶」（⌥→）で順に回れる。どちらを残すかは人が決め、消す方を選んで ⌫
- 表示はふだん「編集後」＝詰めた所が実際に左へ寄った並び（倉田さんの要望）。詰めた継ぎ目には赤い印が付き、ダブルクリックでそこで抜いた所を戻せる。S で「元の音」＝切る前の並び（切る所は赤い帯・ダブルクリックで残す）に切り替わる。データはどちらも元の音の時間で持ち、画面の位置だけを行き来させている
- 色は GarageBand の音声の塊に合わせた青。選んだ塊は白い枠で囲む

## 安全設計

- **元ファイルは読むだけ**。出力はすべて別ディレクトリの別名ファイル
- **同期の根拠が弱ければ止まる**（候補を提示して人間に委ねる。exit 2）。
  「2つの手法が一致したら採用」だけでは不十分だった — 正解が候補に無いと弱い相関同士で一致し、
  誤った値を自信満々に採用してしまう。相関の絶対値が高いことを必須にして塞いだ
- **入力が短すぎたら止まる**（`Buffer.subarray` が無警告で切り詰めるのを防ぐ）
- **出力長が3本で一致しなければ例外**（同期が壊れた成果物を渡さない）
- **捨てた音声を書き出す**（消しすぎていないか耳で確認できる。全トラックを重ねるので、誰の小さな声を切っても気づける）
- **被りは検出するだけで消さない**

## 実装上の注意（ハマった記録）

1. **ffmpeg のフィルタでカットしてはいけない**（区間が数百になるため）
   - `atrim`+`concat` はカット数に対して超線形に遅い（500区間で19秒〜、afade を挟むとさらに悪化）
   - `aselect` は式パーサの再帰深度上限100で落ちる（括弧でグループ化すれば回避可能だが、**フレーム単位でしか切れずサンプル精度にならない**ので結局使えない）
   - → ffmpeg はデコード/エンコードのみ。切り貼りは Node が生PCMのバイト列に対して行う
2. **相互相関だけでは同期できない**。各自の声が自分のトラックで支配的だと共通のかぶり音が弱く、誤ったピークを拾う（実測で正解-1.234sに対し-3.227s）。解析窓を伸ばしても改善しない → 手拍子検出とのクロス検証が必須
3. **移動RMSは clamp しないと NaN になる**。桁落ちで移動和が負に振れ `Math.sqrt` が NaN → 相関全体が NaN → 「オフセット0・スコア0」という一見正常な誤った結果を返す
4. **`Math.max(...array)` は数十万要素でスタックを溢れさせる**
5. **`amix` は使わない**。既定 `normalize=1` が入力数で割るため小声の話者を無音と誤検出する（`amerge` なら可。捨てた音声の書き出しは聞くためだけなので `normalize=0` で使っている）
6. **手拍子を大きさだけで選ぶと、おとりの音に釣られる**（守りのトークン抑え回）。倉田さんの録音では拍手の約6秒前に机やマイクに触れたような余韻の長い音が、かいちさんの録音では81秒に話の途中の物音が、拍手と同じくらい・それ以上の大きさで入っていた → 形（直前が静か・余韻が短い）で見分ける
7. **会話の譲り合いの物差しは3人だと効かない**（ピープルウェアー回）。正解の位置でも -0.02 / +0.08 で、偶然の波形一致（0.65）に負けて -47秒と誤確定した。「同時に声が出ている割合」にしても、話す量が少ない人（最初の10分で1割）が混ざると谷がぶれて決め手にならなかった
8. **頭揃えのずれを自分でサンプルに直さない**（書き出し・守り回）。ずれ 0.445秒は 44.1kHz で 19624.5 サンプルと端数が出る。`src/align.js` が使う ffmpeg の adelay はミリ秒を切り捨ててサンプルにするので、四捨五入した書き出しと1サンプルずれた → 書き出しも align.js と同じ ffmpeg の指定（`-ss` / `adelay`）で頭を揃える
9. **拍手より大きい「拍手でない音」が冒頭にあると、拍手を落とす**（個人開発回・2026-10-23）。3本目は 6.19秒にはっきりした拍手（ほかの拍手らしい音の 19倍）があったが、56.6秒の拍手でない大きな音の 0.40倍しかなく、「最大の音の半分以上」で落ちた。条件をただ緩めると、拍手を切った後の録音で、話の間のクリック音（ほかに拍手らしい音が無い・最大の音の 0.26倍）を拍手と誤った → 「普段の音よりはっきり大きいか」も見る（音合わせの拍手は 2.23倍以上・クリックは 0.95倍）。揃い方は、3本の拍手が同じ時刻にそろう波形と、2人ずつ同時に話している割合の谷（±10秒を探して、3組とも自動の位置から 0.3秒以内）で確かめた
